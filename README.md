# FormFlow — מערכת הטפסים של שווה עסקים 360

מימוש Full-Stack (דמו) של מערכת טפסים חכמה על פי מסמך האיפיון
(`איפיון_מערכת_טפסים_FormFlow.docx`) וחבילת ה-Handoff העיצובית — RTL מלא, עברית
תחילה, בצבעי המותג של מועדון שווה עסקים 360, במצב בהיר ובמצב כהה.

## הרצה

```bash
npm install
npm run dev:full   # שרת API (פורט 4000) + Vite (פורט 5173) יחד
```

או בשני טרמינלים: `npm run server` ואז `npm run dev`.
בילד: `npm run build` (בדיקת טיפוסים + bundle). בלי שרת ה-API הממשק עולה עם
נתוני דמו סטטיים ומציג חיווי "מקומי בלבד".

## ארכיטקטורה

```
shared/    מנוע הכללים + ולידציה + seed — קוד אחד לצד הלקוח ולשרת
server/    Express — יישום עיקרי פרק 7 + SSE + XLSX + Webhooks + היסטוריית גרסאות
           אחסון דרך Adapter: SQLite (better-sqlite3, סכמה לפי פרק 6) עם
           fallback ל-JSON; החלפה ל-PostgreSQL 16 = מימוש Adapter נוסף
src/       React 19 + TypeScript, dnd-kit, TanStack Query, Recharts, lucide
```

- **ולידציה** (`shared/validate.js`) רצה בצד הלקוח ביציאה משדה, ושוב בשרת בעת
  שליחה — מקור האמת (§4.2), כולל ייחודיות ("הערך כבר נשלח בעבר").
- **מנוע לוגיקה** (`shared/rules.js`): תנאים (שווה/שונה/מכיל/גדול/קטן/ריק/מלא)
  בשילוב וגם/או; פעולות בזמן מילוי (הצג/הסתר שדה, קפיצה לעמוד) רצות חיות בטופס
  הציבורי, ופעולות אחרי שליחה (ניתוב מייל, תגית, הקצאה) רצות בשרת (§4.3).
- **Realtime**: SSE (`/events`) דוחף `submission.created` לדשבורד פתוח —
  שורה חדשה נכנסת עם הבהוב בלי רענון (§4.6.2).
- **ייצוא**: XLSX אמיתי (ExcelJS, גיליון RTL עם כותרת מעוצבת) או CSV, מכבד את
  הסינון הפעיל (§4.6.3).

## API (עיקרי פרק 7)

| Method | Endpoint | תיאור |
|---|---|---|
| GET | `/api/v1/forms` · `/forms/:id` | רשימה / טופס מלא |
| PATCH | `/api/v1/forms/:id` | שמירת שדות/כללים/התראות/מיתוג (Autosave מהבילדר) |
| POST | `/api/v1/forms/:id/publish` | פרסום גרסה |
| GET/POST | `/api/v1/forms/:id/submissions` | שליפה מסוננת / שליחה ציבורית מאומתת |
| GET/PATCH | `/api/v1/submissions/:id` | פרטי תשובה + התראות / עדכון סטטוס·תגיות·הערות |
| GET | `/api/v1/forms/:id/analytics` | KPI, ציר זמן, התפלגויות |
| GET | `/api/v1/forms/:id/export?format=xlsx\|csv` | ייצוא לפי הסינון |
| GET | `/api/v1/forms/:id/versions` · `/versions/:vid` | היסטוריית גרסאות (עד 50) |
| GET/POST | `/api/v1/forms/:id/webhook-logs` · `/webhook-logs/:id/retry` | לוג קריאות Webhook + שליחה חוזרת |
| POST | `/api/v1/notifications/test` | שליחת בדיקה |
| GET | `/api/v1/forms/:id/events` | סטרים SSE |

| 04 · לוגיקה מותנית | `/form/conf-2026/logic` | עורך כללים מלא (תנאים+פעולות), הפעלה/כיבוי, שכפול/מחיקה |
| 05 · הגדרות | `/form/conf-2026/settings` | פאנלים מלאים: התראות (תצוגה חיה, נמענים, SMS), Webhooks (§4.9.2 — ניהול + לוג + Retry), פרסום והפצה (§4.8 — קישור/QR/הטמעה + הגבלות), כללי, גישה והרשאות |

| 08 · מצב כהה | כל הממשק | טוקני dark מלאים |

| נוסף · תבניות | `/templates` | ספריית תבניות לפי קטגוריות (§4.7.1) — "שימוש בתבנית" נכנס לאשף |
| נוסף · היסטוריית גרסאות | בבונה (אייקון שעון) | עד 50 גרסאות Autosave עם שחזור (§4.1.1) |
| תהליך · התחברות (Connect) | `/login` | מייל+סיסמה עם ולידציה, SSO ‏Google/Microsoft, אימות דו-שלבי TOTP (§5.3), תפריט משתמש והתנתקות |
| תהליך · Onboarding | `/onboarding` | שלושה צעדים: שם Workspace ותחום, מטרה ראשונה, הזמנת צוות — עם באנר השלמה במסך הבית |
| תהליך · אשף טופס חדש | `/new` | צעד-אחר-צעד: תבנית/מאפס ← שם ותיקייה ← בחירת שדות ← התראות וסיכום — ובסיום נוצר טופס אמיתי בבונה, בשרת ובטופס הציבורי |

בנוסף, כל תשובה חדשה מפעילה Webhooks פעילים (סימולציה עם רישום בלוג), והבונה
שומר גרסה בכל שינוי שדות.

## תרחיש דמו מומלץ

1. פתחו את הדשבורד (`/form/conf-2026/responses`) בטאב אחד.
2. מלאו את הטופס הציבורי בטאב שני: בעמוד 1 בחרו "כן, חברי מועדון" + 7 משתתפים
   (תנאי ה-VIP), בעמוד 2 בחרו מסלול "עיצוב ו-UX" — שדה הסדנה יופיע לפי הכלל.
3. שלחו — מסך האישור יציג את הניתוב ל-`vip@shaveh360.co.il`, והשורה תיכנס
   לדשבורד בטאב הראשון בזמן אמת עם תגית VIP.
4. נסו לשלוח שוב עם אותו מייל — השרת ידחה (ולידציית ייחודיות).

## ריבוי לקוחות (Workspaces) והרשאות

- כל כניסה למערכת דורשת התחברות (`/login`, כולל Google/Microsoft SSO ו-MFA);
  משתמש חדש מקבל Workspace משלו ועובר Onboarding לפני הטופס הראשון.
- **הפרדה מלאה בין לקוחות**: כל קריאות ה-API מזוהות (כותרת `X-User-Email`)
  ומסוננות לפי ה-Workspace — רשימת טפסים, תשובות, analytics, ייצוא, גרסאות
  ו-Webhooks. גישה לטופס של לקוח אחר מחזירה 404. הטופס הציבורי (`/f/:slug`)
  נשאר פתוח לממלאים דרך endpoint ציבורי מצומצם.
- חשבונות הדמו `israel@gmail.com` / `israel@outlook.com` (כפתורי ה-SSO) נכנסים
  ל-Workspace המוכן עם 5 טפסי הדוגמה; כל מייל אחר מתחיל ריק.
- **אשף הטופס** (`/new`) מקים טופס אמיתי בשרת (POST /forms) ואז נפתח הבונה
  על הטופס החדש; מחיקת טופס שואלת האם למחוק גם את הרשומות, ומחיקת רשומה
  בודדת זמינה מחלונית התשובה.

## פריסה ל-Vercel (דמו סטטי)

הרפו מוכן לייבוא ישיר: `vercel.json` מגדיר SPA rewrites, ו-better-sqlite3 הוא
תלות אופציונלית כך שההתקנה לא נכשלת בסביבת Build ללא כלי קומפילציה.

1. https://vercel.com/new ← Import Git Repository ← בחרו את `formflow`
2. Vercel מזהה Vite אוטומטית (Build: `npm run build`, Output: `dist`) — פשוט Deploy

בפריסה סטטית אין את שרת ה-API, ולכן האפליקציה עוברת ל**מצב דמו** אוטומטי:
כל המסכים והתהליכים פועלים עם נתוני הדמו, ושליחת הטופס הציבורי מדמה את צינור
ההתראות עם חיווי "מצב דמו". להרצה מלאה (SQLite, ‏SSE, ייצוא, Webhooks) צריך
אירוח עם תהליך Node מתמשך — Render / Railway / Fly — עם `npm run server`
והגשת ה-frontend מאותו שרת או עם proxy.

## הערות

- הלוגו placeholder וקטורי — להחליף ב-SVG הרשמי בכל המופעים.
- אחסון השרת הוא קובץ JSON לצורכי דמו; באיפיון: PostgreSQL + תורים (פרק 8).
- `POST /api/v1/__reset` מאפס את נתוני הדמו (משמש את חבילת ה-E2E).
